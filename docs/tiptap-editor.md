# TipTap Editor

## Overview

The card editor in Flux uses [TipTap](https://tiptap.dev) — a headless, ProseMirror-based rich text editor. It replaces the previous raw-markdown textarea, giving users a true WYSIWYG experience: bold text renders as **bold**, lists render as bullet points, and checkboxes work interactively — all while typing.

The backend stores content as plain markdown (`content_markdown` on the `Card` model). TipTap reads from and writes back to markdown via the `tiptap-markdown` extension, so the data contract is unchanged.

## How It Works

### Initialisation

`TipTapEditor` receives `value` (markdown string from the card) and `onChange` (called on every edit). The editor initialises once with `content: value` passed to `useEditor`. TipTap parses the markdown into a ProseMirror document via the `Markdown` extension.

```tsx
const editor = useEditor({
  extensions: [
    StarterKit,
    Underline,
    TaskList,
    TaskItem.configure({ nested: false }),
    Markdown.configure({ html: false, tightLists: true }),
  ],
  content: value,
  onUpdate({ editor }) {
    onChange(editor.storage.markdown.getMarkdown())
  },
})
```

### Switching Cards

`EditorPanel` renders `<TipTapEditor key={card.id} ... />`. The `key` prop causes React to fully remount the editor whenever the selected card changes, ensuring the new card's content loads cleanly with no state bleed from the previous card.

### Auto-save

`EditorPanel` owns the save logic:

1. `TipTapEditor.onChange` fires on every keystroke → updates `content` state in `EditorPanel`
2. `useDebounce(content, 800)` waits for 800 ms of inactivity
3. `useUpdateCard` mutation fires → `PATCH /api/v1/cards/:id/` with `content_markdown` and `content_preview` (first 200 chars)

The editor itself has no knowledge of saving — it only calls `onChange`.

### Formatting Toolbar

The toolbar lives inside `TipTapEditor` since it needs direct access to the editor instance. Each button calls a TipTap chain command and highlights when the cursor is inside a matching mark/node:

```tsx
editor.chain().focus().toggleBold().run()
editor.isActive("bold") // → true when cursor is inside bold text
```

Toolbar buttons use `onMouseDown` with `e.preventDefault()` to avoid the editor losing focus on click.

## Supported Formatting

| Feature | How to use |
|---------|-----------|
| **Bold** | Toolbar button or `Cmd/Ctrl + B` |
| _Italic_ | Toolbar button or `Cmd/Ctrl + I` |
| Underline | Toolbar button or `Cmd/Ctrl + U` |
| Bullet list | Toolbar button |
| Checklist | Toolbar button; checkboxes are interactive |
| Headings | Type `# `, `## `, `### ` at line start |
| Code | Wrap in backticks or type ` ``` ` for a code block |
| Blockquote | Type `> ` at line start |
| Undo / Redo | `Cmd/Ctrl + Z` / `Cmd/Ctrl + Shift + Z` |

## Styling

TipTap renders a `contenteditable` div. Styles are applied via:

1. **`editorProps.attributes.class`** — adds `tiptap-content` class to the root element
2. **`.tiptap-content` rules in `src/index.css`** — scoped styles for headings, lists, task list checkboxes, code, blockquotes, and spacing

These styles live in `index.css` rather than inline Tailwind classes because they need to target descendant HTML elements generated by ProseMirror (e.g. `ul[data-type="taskList"] li label input`).

## Known Limitations

- **No placeholder text** — TipTap's placeholder extension (`@tiptap/extension-placeholder`) is not installed. The `.is-editor-empty` CSS rule in `index.css` is a stub for when it gets added.
- **No image support** — Images require `@tiptap/extension-image`. Not needed for the current use case.
- **Task item nesting disabled** — `TaskItem.configure({ nested: false })` keeps checklists flat. Can be enabled later.
- **`tiptap-markdown` is a community package** — When TipTap releases an official markdown extension (currently Pro-only), this can be swapped with a one-line change in `TipTapEditor.tsx`.
